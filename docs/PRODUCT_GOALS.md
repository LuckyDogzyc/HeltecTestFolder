# Pokémon 墨水屏价格牌：产品目标与版本权益

> 状态：已确认产品方向。后续账号、权益、配置下发与支付相关设计、开发和验收均以本文为准。

## 1. 产品目标

将当前 ESP32 宝可梦价格显示设备发展为同时提供免费版与付费版的云端管理产品。

用户在公网 WebUI 中管理自己名下的设备和显示内容；设备通过既有的云端配置拉取机制，在下次唤醒时自动获得可用配置与画面。

**用户开通或续订付费版后，不得要求重新刷写固件、OTA 更新或重新配网。**

## 2. 免费版

免费版保留当前已实现的基础能力，作为可直接使用的产品版本：

- 设备联网、注册和远程管理；
- 基础卡牌搜索与价格显示；
- 基础官方模板；
- 云端保存配置；
- 设备按既有低功耗唤醒周期获取配置/价格并刷新；
- 三色墨水屏完整帧显示与本地动态槽位（如价格、日期、时间、电量）。

免费版的具体设备数量、可绑定卡牌数量、模板数量等限制，后续通过权益配置定义，不在固件中写死。

## 3. 付费版

付费版在免费版基础上开放更多高级自定义能力，至少包括：

- 更多模板和更高的自定义额度；
- 自由排版与高级显示组件；
- 上传图片、Logo 等静态素材并显示到墨水屏；
- 品牌/背景/图片类模板；
- 后续可扩展的多设备、轮播内容及其他高级权益。

具体收费档位、价格、免费版与付费版的数量上限，以及支付渠道在权益模型完成后另行确定。

## 4. 核心技术原则：权益在云端，设备无需升级

ESP32 固件必须保持为通用显示终端，不在设备中固化“免费版”或“付费版”业务判断。

```text
用户账号
  -> 认领/绑定设备
  -> 云端记录权益（free / pro / 后续套餐）
  -> WebUI 按权益开放编辑与素材能力
  -> 服务端校验权益、渲染最终三色画面、递增 configVersion
  -> ESP32 下次唤醒拉取配置并显示
```

因此：

- 用户购买成功后，由服务器更新其权益；
- 服务端为该用户的设备开放高级配置并更新 `configVersion`；
- 设备沿用现有配置拉取、黑/红双平面 frame 和动态槽位协议；
- 设备下一次唤醒即可得到付费能力对应的画面；
- 开通付费版不依赖固件更新、OTA、重新配网或客户手工操作设备。

## 5. 后续软件实施顺序

1. 将当前 MVP 的演示设备存储迁移为正式数据库；
2. 实现账号注册、登录、设备认领/绑定及设备归属隔离；
3. 建立通用权益（entitlement）模型，WebUI 与服务端均按权益校验；
4. 完成免费/Pro 的首条端到端功能链路：免费基础模板，Pro 高级布局/图片素材；
5. 服务端统一保存配置、渲染三色 frame 并向设备下发；
6. 最后接入支付订单与支付回调，将人工授予 Pro 替换为自动权益开通。

## 6. 验收标准

- 免费账号仅能使用免费版允许的功能；
- Pro 账号可以使用已授权的高级自定义和图片素材功能；
- 用户只能查看、编辑和管理自己认领的设备；
- 不具备相应权益时，前端入口和服务端保存接口均必须拒绝高级配置；
- 用户权益从免费版变为 Pro 后，无须刷机或 OTA；
- 设备下次正常唤醒后可拉取并显示 Pro 配置；
- 无论免费或 Pro，设备继续使用当前低功耗、缓存和 `304` 不刷新策略。
